# 멜론 수집 상한과 부분 실패

2026-10-14. 멜론 목록과 티켓 오픈 공지 수집을 대상으로 한 보강이다. 과거 `source timeout 90s`의 정확한 제공자와 재현 조건은 확인되지 않았으므로 그 운영 장애의 원인을 확정했다고 주장하지 않는다.

- 목록 요청8초. 공지 수집 전체12초, 요청당 최대5초, 동시 최대2개·최대3페이지. 헤더와 본문 읽기를 포함한 AbortController 타이머가 실제 요청을 취소하며 작업 정리 후 반환한다.
- 실패 응답이나 차단 페이지를 다른 전송 방식으로 우회하지 않는다. 성공 응답만60초·최대32개 메모리 캐시에 저장한다.
- 목록 JSON의 형태와 공지 목록 wrapper·행의 닫힘·ID·제목을 검증한다. 페이지 일부가 망가졌으면 정상인 완전한 행만 보존하고 `ok:false`, `partial:true`, 오류와 완료 페이지 수를 표시한다. 망가진 문서는 캐시하지 않는다.
- 진짜 빈 목록과 구조가 깨진 빈 결과를 구분한다. 모르는 장소·가격·일정은 추정하지 않는다.
- 회귀10개 그룹: 헤더/본문 타이머 실제 실행, abort 이후 active0, 동시성·호출수 상한, 성공 형제 페이지 보존, TTL 만료 후 실패, 403/잘못된JSON, 혼합 정상·비정상행, 닫히지 않은목록/행, 비정상문서 미캐시, 집계API 부분실패.
- 별도 실제 읽기에서 목록43건, 공지3페이지12개를 확인했다. 각각 관측 당시 정상 응답이며 지속 가용성이나 모든 공연을 수집한다는 보증이 아니다.

남은 범위: 다른 판매처의 공통 timeout race, `service.mjs` 페스티벌 상세/국적 보강의 직렬 호출, 원천 자체의 차단·누락, 이미지로만 발표한 라인업은 이 변경의 해결 범위가 아니다. 동시성 상한은 수집 호출별이며 서버 전체의 전역 상한은 아니다.
