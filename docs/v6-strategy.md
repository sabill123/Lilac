## 2. 타깃

**한국·J-POP (Lilac 코리아)** — 한국에 사는 20~30대 J-POP 팬.
- 해야 하는 일: 내한 공연을 놓치지 않기 → 티켓 오픈 시각 맞추기 → 일본반·특전 사기 → 일본 현지 공연(원정) 추첨 기간 챙기기.
- 지금의 불편: 내한 공지가 인터파크·멜론·예스24·기획사 SNS에 흩어짐. 일본 판매처는 일본어·해외배송 여부가 제각각. 일본 추첨(先行抽選) 일정은 일본어로만 공지.

## 7. 팬클럽 선행·전용 (v6.1)

일본은 팬클럽 선행이 사실상 1차 판매다. 예매처에 없다고 숨기면 가장 중요한 공연이 빠진다. 그래서 팬클럽 전용 공연도 보여 주고, 가입 방법을 안내한다. 팬은 신청 경로를 얻고, 소속사는 팬클럽 가입자를 얻는다.

- **찾기**: 로스터의 공식 사이트 → 가입(入会) 링크를 점수로 고른다(문구·경로·팬클럽 하위 도메인). PLUS MEMBER 사이트는 `/feature/entry` 같은 공통 경로를 쓴다. 투어 특설·티켓 공지 페이지도 함께 모은다.
- **가입 정보**: 팬클럽 이름, 연회비·월회비·입회금, 해외 거주자 가입과 해외 요금, 결제 수단(`できません` 표기는 제외), 가입 페이지 언어. 없는 값은 null로 두고 화면에는 "가입 페이지에서 확인"이라고 쓴다.
- **접수**: `受付期間` 블록마다 이름·기간(+09:00)·조건. 팬클럽 전용(`申込者・同行者ともに…会員`), 해외 거주자 선행, 일본 번호 없이 가능, 누구나 신청(`どなたでも`, 편의점·예매처 선행), 회원 공식 리세일을 구분한다. 리세일은 선행 목록에 섞지 않고 아티스트 화면에만 둔다.
- **공연 회차**: 페이지마다 배치가 달라 세 가지를 모두 읽는다. 한 줄(날짜+도·현・공연장), 날짜 다음 줄 공연장, 공연장 아래 날짜들(특설 페이지 표). 어느 쪽인지는 페이지 전체의 배치로 정한다. 표 머리의 도시 이름(SEOUL·TAIPEI·Kagawa 등)과 한국 공연장 이름으로 나라를 정해, 일본 아티스트의 서울 공연은 **내한**으로, 일본 공연은 **일본 원정**으로 나눈다. 판매 장소·중지 공지·문의처는 공연으로 읽지 않는다. 규칙은 `tests/verify-fanclub.mjs`가 합성 HTML로 고정한다.
- **화면**: 홈 "팬클럽 선행 접수 중", 공연·티켓의 "팬클럽 선행·전용 공연" 묶음, 티켓 오픈 목록(창마다 따로), 아티스트 화면의 공식 팬클럽 카드와 5단계 가입 방법, 상세 시트 안내. 접수 이름은 공식 명칭 그대로 두고 성격은 태그로 설명한다.
- **소속사 지표(BM 2단계 근거)**: 가입·신청 링크에 `utm_source=lilac`을 붙이고, 누른 횟수를 아티스트·날짜별로만 센다(개인 정보 없음). `/api/live/fc-referrals`, 상태 화면에 표로 보인다.

## 8. 홈 — 이전 홈과 합치기 (v6.1)

- 맨 위: 이전 홈의 레코드 무대(이 에디션 차트 1~3위 3D 레코드, 레코드 선택, 30초 미리듣기). WebGL2가 없거나 데이터 절약·동작 줄이기면 정적 재킷. 새 토큰(밝은 배경·라일락 강조)으로 다시 짰다.
- 그 아래는 v6 순서 그대로: 다가오는 내한 공연 → 티켓 오픈·팬클럽 선행 → 최신 소식·차트 → 새 앨범 → 현지 공연.
- 아티스트 앞에 이전 홈의 음악상·연말무대(대회별 공식 비주얼). 일본어 화면에서는 부문·설명을 일본어로 옮긴다.
- 이전 홈의 발견 선반 중 "상승·새로 진입"은 차트 화면으로 옮겼다. 이전 순위를 주는 차트(Billboard JAPAN Hot 100)가 있을 때만 그리고, 없는 나라는 그리지 않는다.

## 9. v7 화면 — 3D 무대와 "AI 같은" 요소 걷어내기

실제 서비스에서 뽑은 기준(2026-09-27, 브라우저에서 계산된 스타일을 직접 측정):

| 서비스 | 측정값 | 가져온 것 |
|---|---|---|
| NOL 티켓 홈 | 카드 제목 18px/600, 보조 14px 회색(#6e6f73), 섹션 제목 24px/700, 섹션 부제 없음, 테두리 있는 요소 1159개 중 15개, 포스터 반경 16px. 오픈 예정 카드는 흐린 포스터 배경 위에 포스터, 아래 첫 줄이 강조색 오픈 시각("내일 14:00") | 티켓 오픈 카드, 부제 없는 섹션 제목, 오픈 시각을 첫 줄에 |
| Apple Music(웹) | 쪽 제목 34px/700, 섹션 제목 17px/700 + 전체보기, 재킷 반경 5~7px, 테두리 0개, 가로 선반 | 가로 선반과 앞뒤 버튼, 테두리 없는 재킷, 흐린 사진 머리(아티스트) |
| 멜론티켓 | 제목 자간 -1px, 오픈 줄 "[오픈]26.09.28(월) 20:00" 회색 13px | 좁은 자간, 날짜 서식 |
| Apple Music 소개 페이지 | 어두운 띠 위 80~128px 제목, 밝은 띠와 번갈아 | 어두운 무대 + 밝은 본문 |

바꾼 것
- 홈 무대: LP 레코드를 걷어내고 곡면 포스터 갤러리(three.js)로. 원통 안쪽에 공연 포스터가 둘러서고, 카드 면이 정점 셰이더에서 곡면으로 휜다. 끌기·관성·스냅, 트랙패드 좌우, 방향키, 5.2초 자동 넘김(만지면 멈춤), 움직이는 속도에 따른 물결·기울임·색 번짐, 초점 카드만 선명, 바닥 반사, 포인터 시차. 배경에는 초점 포스터를 아주 흐리게 깔아 색이 바뀐다. WebGL이 없으면 같은 포스터를 CSS 3D로 접어 보여 준다. 화면 밖·탭 숨김·동작 줄이기에서는 그리지 않는다.
- CORS 헤더가 없는 예매처 이미지(티켓피아 등)는 `/api/live/img`로 중계한다(허용 호스트만, 6MB 제한, 메모리 80장).
- 섹션 부제, 방법 설명 문단, 점선 빈 상자, 파스텔 칩을 없앴다. 출처는 쪽 맨 아래 한 줄("정보 제공 …").
- 공연 상세 시트: 흐린 포스터 위 포스터·제목·버튼, 아래는 규칙선 표(예매처 상세 화면 구조).
- 팬클럽 안내: 상자 없이 가입 정보 표와 01~05 단계. 문장은 짧은 명사형으로.

## 10. v8 — 헤더와 "정보가 없다" 문제

헤더 기준(2026-09-27 측정): NOL은 1행 로고·검색(400×48)·아이콘+글자(마이·찜·장바구니), 2행 카테고리 18px(현재 메뉴만 강조색 굵게). 멜론티켓은 맨 위 12px 회색 글자 줄(로그인·회원가입·고객센터·이용안내) → 로고·검색 → 카테고리 줄.

## 15. v14 — 실시간 동기화 · 막힌 원천 우회 · 로스터 신원 · 색과 헤더

**실시간 동기화.** 예전에는 요청이 올 때 TTL이 지났으면 갱신하고 45분마다 한 번 데웠다. 화면은 새로고침해야 바뀌었다.
- 서버: 원천마다 주기를 따로 둔 백그라운드 동기화(`SYNC`) — 티켓 오픈 공지·뉴스 5분, 来日·내한 공연 10분, 국내 K-POP 20분, 팬클럽 선행 접수(열려 있거나 곧 열리는 팀) 30분, 로스터 신원 확인 15분, 사진 30분. 상태는 `/api/live/status` → `realtime`.
- 캐시(`cache.mjs`): 갱신 결과를 해시로 비교해 **바뀐 경우에만** `change` 이벤트(새 항목 수 `added` 포함). 수집 시각 같은 휘발 필드는 비교에서 뺀다. 실패·전부 0건은 이전 값을 지키고 알리지 않는다.
- `/api/live/stream`(SSE): 주제(concerts·tickets·news·fanclubs·charts·community·fx)별로 1.5초 모아 알린다. 키별 새 항목 수(`byKey`)를 실어 화면이 자기 에디션 것만 센다. 차트 수집·환율·커뮤니티 글/댓글도 같은 통로.
- 화면(`live.ts`): EventSource 구독 → 지금 보는 화면과 관련된 주제만, 조작이 2.5초 멈추고 입력·시트가 닫혀 있을 때 화면 밖 그릇에 다시 그려 바꿔 끼운다(스크롤 유지). 홈은 3D 무대를 두고 아래 목록만. 헤더에 연결 상태와 마지막 갱신 시각.
- 검증: `tests/verify-realtime.mjs`(같은 내용 → 알림 없음, 늘면 added, 실패·0건은 이전 값 유지).

**막힌 원천 우회.**
